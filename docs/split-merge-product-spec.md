# split / merge 产品规格（本地持久化知识加工工序）

> 状态：由实现方按用户 2026-11-28 任务口径补建；产品语义以用户维护为准。

## 定位

split / merge 是 Ember2 本地明文知识库中的持久化知识加工工序，不是临时对话上下文管理。节点与结果随画布落盘，可反复执行与撤销。

## 目标

1. 把「分块 → 提炼 → 汇总」嵌入可执行的持久化知识流。
2. 分块与预算计算在本地纯逻辑层完成，按本地 / 公网 provider 差异化。
3. 执行语义完整：进度、取消、重跑确认、整批一条历史。

## 不可妥协语义

1. 块可编辑；编辑后 merge 读取块当前内容，不回写上游原文，不承诺映射回原文偏移。
2. 重跑 split 整批覆盖前必须二次确认，文案说明已编辑块会被覆盖。
3. refine 运行期块只读，运行结束（成功 / 失败 / 取消）恢复可编辑。
4. merge 超预算报错，不静默截断。
5. 整批 split / merge 只占一条历史，可一次 undo；取消无残留节点，历史栈干净。
6. 分块与预算计算在本地纯逻辑层，不依赖云端。

### 语义 5 的例外：merge → document 输出

当且仅当 merge 的输出目标是 document 时，结果走文档层整篇写入，不进入画布撤销栈；Ctrl/Cmd+Z 不会回滚该次文档写入。UI 在 merge 卡片常驻提示「文档写入不进入画布撤销」。

该例外不适用于「双输出」。当前实现中，若 merge 同时存在文本输出与 document 输出，runner 以「输出目标不唯一」拒绝执行，不会静默选择任一输出，因此不构成 document 例外。卡片提示复用同一输出形态判定（`mergeOutputKind`），仅在唯一 document 输出时显示，不再误报。

该例外不改变语义 5 对画布内 split / merge 批次历史的约束；如需文档写入也纳入统一撤销，另立需求。

## 验收标准

- v3 round-trip。
- 编辑第 k 块后，merge 使用编辑后的内容。
- 取消后无残留节点，历史栈长度回到操作前。
- 整批操作只有一条历史。
- refine 运行期块不可编辑。

## 不做什么

- 不做「保留手动修改块」分支。
- 不做分层递归汇总。
- 不做自动备份 / `.v2.bak`。
- 不做静默截断。
- 不新增编辑态 / 锁定 / offset / length 字段。
- 不为未实现能力预留字段。
- 不重写已落地的格式层与渲染卡片；只做增量补。
